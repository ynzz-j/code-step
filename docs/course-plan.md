## 五、课程设计规范

### 5.1 单步设计原则

每个课程步骤应遵循以下原则：

| 原则 | 说明 | 示例 |
|------|------|------|
| **单一概念** | 每个步骤只教一个概念 | ✅ "学习 if 语句" / ❌ "学习 if、循环和数组" |
| **小步快跑** | 每个步骤控制在 2-5 分钟 | 8-12 个步骤构成一个课程 |
| **即时反馈** | 立即告诉用户对错 | 打字模式：逐字符高亮 |
| **正向激励** | 鼓励性文案，减少挫败感 | "很好！""继续加油！" |
| **刻意练习** | 关键代码需要打字练习 | main 方法、常用语法用 typing 模式 |

### 5.2 步骤类型分布

建议每个课程中两种模式的比例：

```
┌─────────────────────────────────────┐
│         步骤类型分布                 │
├─────────────────────────────────────┤
│                                     │
│   Typing 模式 (40-50%)             │
│   ├── 固定写法必须记住               │
│   ├── 关键字、语法结构               │
│   └── 建立肌肉记忆                   │
│                                     │
│   Coding 模式 (50-60%)             │
│   ├── 灵活应用所学知识               │
│   ├── 小改动完成练习                 │
│   └── 培养编程思维                   │
│                                     │
└─────────────────────────────────────┘
```

```json

  "id": "course-id",

  "difficulty": "beginner|intermediate|advanced",

    {
      "type": "coding|typing",

      "instruction": "学习说明（Markdown 格式）",
      "hint": "提示内容",
      "starter": "起始代码（coding 模式）",
      "answer": "参考答案",
      "expectedOutput": "期望输出",
      "targetCode": "目标代码（typing 模式）",
      "encouragement": "鼓励文案"
    }
  ]
```

### 6.2 开发检查清单

- [ ] 课程 ID 唯一且符合规范 `语言-主题`
- [ ] 标题简洁，15 字以内
- [ ] 说明文案清晰，避免歧义
- [ ] 起始代码可运行（无语法错误）
- [ ] 参考答案正确
- [ ] 提示内容有帮助但不直接给答案
- [ ] 打字模式代码长度适中（10-20 行）
- [ ] 每步骤有鼓励文案
- [ ] 概念标签准确
- [ ] 难度分级合理
